Distributed Microservices Architecture

Visual blueprint, Entity-Relationship model, and UML choreographies of the Travel2Go travel booking platform.

🛡️ Invariant G1: Zero Convenience Fee
All amounts stored as Long paise. The booking fee (feePaise) across bookings, quotes, and payments must strictly equal 0L.
🔐 Invariant G2: Cryptographic Quote Token
Prices sealed via server-signed HMAC-SHA256 tokens over { legId, pricePaise } with 15-min TTL. Client price tampering throws immediate rejections.
⚡ Transactional Outbox & DLQ
PostgreSQL atomic ledger updates with outbox polling via FOR UPDATE SKIP LOCKED. RabbitMQ consumers feature bounded retries & dead-letter queues.

📦 Microservices Fleet & Infrastructure Ports Matrix

Inventory of active ports, datastores, endpoints, and responsibilities across the container fleet.

🚪 api-gateway
:8080
Spring Cloud Gateway reverse proxy fronting all microservices, rate-limiting, and Actuator probes.
  • Routes: /api/**, /oauth2/**
  • Security: DownstreamUrlValidator, JWT Pass-through
  • Health: /actuator/health/readiness
🔑 identity-service
:8081
User authentication, BCrypt verification, Google OAuth2 redirect flow, and Twilio SMS OTP.
  • Endpoints: /api/auth/**, /api/users/**
  • Datastore: Cloud Firestore (users, verification_codes)
  • Integrations: Google OAuth2, Twilio API
🌴 package-service
:8082
Tour packages, custom itineraries, room allocation matrices, and seasonal pricing engines.
  • Endpoints: /api/packages/**, /api/allocation-rules/**
  • Datastore: Cloud Firestore (holiday_packages, allocation_rules)
  • Features: Hotel & transport allocation calculations
📅 booking-service
:8083
Leg bookings orchestrator, CRM leads pipeline, and participant in saga leg confirmation.
  • Endpoints: /api/bookings/**, /api/leg-bookings
  • Events: Consumes booking.leg-confirmed (DLQ enabled)
  • Resilience: NotificationClientFallbackFactory
🖼️ media-service
:8084
Cloud media asset manager with direct Google Cloud Storage bucket integration.
  • Endpoints: /api/media/upload, /api/media/all
  • Storage: Google Cloud Storage (Bucket: travel2go-media)
  • Features: Context tag indexing and public URL resolution
🔔 notification-service
:8085
Dispatches transactional emails, SMS alerts, and dynamically generates PDF invoices.
  • Endpoints: /api/notifications/**
  • Engines: JavaMailSender, Twilio SDK, iText PDF
  • Features: Indian number-to-words currency formatting
⚡ reactive-booking-fn
:8086
Non-blocking Project Reactor consumer streaming real-time metrics to Redis caches.
  • Runtime: Spring WebFlux reactive Netty
  • Broker: RabbitMQ reactive AMQP stream
  • Cache: Redis live counters & analytics
🧭 trip-service
:8087
Journey backbone owning Trips and Legs. Computes quotes, issues HMAC tokens, and handles payment captures.
  • Endpoints: /api/trips/**
  • Security: QuoteTokenService (HMAC signing)
  • Events: Consumes payment.captured, publishes leg.confirmed
💳 payment-service
:8088
Double-entry money ledger, Razorpay integration, webhook signature validation, and OutboxRelay.
  • Endpoints: /api/payments/order, /api/payments/webhook
  • Datastore: Cloud SQL PostgreSQL 15 (payment_ledger)
  • Outbox: Scheduled poller with FOR UPDATE SKIP LOCKED
REDIS Cache
:6379
High-speed in-memory data store for idempotency protection and real-time streaming counters.
  • Role: 24h event deduplication keys & booking metrics cache
  • Consumer: reactive-booking-function (ReactiveRedisTemplate)
  • Engine: Redis 7 Alpine container / Managed Memorystore
RabbitMQ Message Broker
:5672 / :15672
Asynchronous choreography bus driving payment capture events and leg confirmations with DLQs.
  • Exchanges: trip.exchange, payment.exchange (Topic)
  • Dead Letter Queues: trip.dlx, booking.dlx (Bounded retry)
  • Management UI: Port 15672 web interface
Cloud SQL PostgreSQL 15
DB Ledger
ACID double-entry financial ledger owning payment transactions and transactional outbox.
  • Database: payment_ledger (instance pg-travel2go)
  • Tables: payments, outbox, processed_webhook_events
  • Pattern: Transactional Outbox with SKIP LOCKED polling
Google Cloud Platform (GCP)
Cloud Run
Primary cloud foundation providing reactive NoSQL persistence, object storage, and compute.
  • Datastore: Cloud Firestore (travel2go-db, region asia-south2)
  • Object Storage: Cloud Storage (Bucket: travel2go-media)
  • Compute: Cloud Run Zero-Trust containers (dedicated SAs)
